Subtask 競品分析與規格草稿

Trello · Asana · Linear｜查閱日期：2026-07-29

功能對照 我方缺口 規格草稿 Trello Brief Asana Brief Linear Brief

研究範圍

目標使用者透過 subtask 拆解任務細節。我方產品目前沒有 subtask，但既有 task 已有狀態、負責人與截止日。[O1]

證據界線：競品事實只採官方來源直接呈現的內容；「未能確認」不代表功能不存在。規格段落屬我方提案，不是競品事實。

1. 功能對照表

功能面向 Trello Asana Linear
資料模型 Card 內的 checklist item；可轉成獨立 card。[T1] 嵌在父 task 內的獨立 task，具有相同欄位。[A1] Sub-issue 與另一個 issue 建立 parent 關係。[L1]
建立入口 Card → Checklist → Add an item。[T1] Task details pane → Subtasks；亦支援右鍵或 Tab+S。[A1] Parent issue → + Add sub-issues；亦支援 command menu。[L1]
完成狀態 使用 checkbox 完成，並顯示數量與完成比例。[T1] Subtask 獨立完成；父 task 完成不會自動完成 subtasks。[A1] Issue 具有 status；父子自動關閉可由團隊選擇設定。[L1][L2]
負責人／截止日 Advanced Checklist 可設定一位負責人與截止日。[T2] Task 模型包含 assignee、完成狀態與 due date。[A1][A2] Assignee 可在特定條件下繼承；sub-issue 截止日行為未能從查閱頁面直接確認。[L1]
多層結構 未能確認。 最多 5 層 subtasks。[A1] 未能確認最大層數。

2. 我方缺口

缺口 1：缺少父子任務關係

我方現況：目前 task 沒有 subtask。[O1]

競品證據：Asana 使用 parent task／subtask，Linear 使用 parent issue／sub-issue；Trello 提供 card 內 checklist item。[T1][A1][L1]

差距：使用者無法在一個任務內建立可追蹤的細分工作。

缺口 2：缺少任務內拆解入口與進度摘要

我方現況：沒有已確認的 subtask 建立入口或進度摘要。[O1]

競品證據：三者都從父工作項目的詳細頁面提供入口；Trello 另顯示項目數與完成比例。[T1][A1][L1]

差距：使用者無法在查看父任務時直接拆解工作並掌握完成程度。

缺口 3：既有欄位無法套用至細分工作

我方現況：Task 已有狀態、負責人與截止日，但沒有 subtask 可承載。[O1]

競品證據：Asana subtask 使用 task 欄位；Trello advanced checklist 支援負責人與截止日；Linear sub-issue 支援 status 與條件式 assignee 繼承。[T2][A1][A2][L1]

差距：任務拆解後無法分別指派、排程或追蹤。

提案

3. 規格草稿

User story

作為任務負責人，我希望能在任務內建立 subtask，並分別設定狀態、負責人與截止日，以便拆解工作細節並追蹤各部分進度。

證據依據：[T1][T2][A1][A2][L1][O1]

AC1：建立 subtask

  • Given：使用者有權編輯一筆 task。
  • When：在 task 詳細頁選擇「新增 subtask」並輸入名稱。
  • Then：建立 subtask，顯示於父 task 的 subtask 區塊並保留父子關係。

AC2：管理 subtask 欄位

  • Given：父 task 已有一筆 subtask。
  • When：使用者開啟或編輯該 subtask。
  • Then：可設定名稱、狀態、負責人及截止日。

AC3：顯示父子脈絡

  • Given：使用者正在查看 subtask。
  • When：subtask 詳細資料開啟。
  • Then：畫面顯示其父 task，並允許返回父 task。

AC4：顯示完成進度

  • Given：父 task 包含一筆以上 subtask。
  • When：任一 subtask 的狀態改變。
  • Then：父 task 顯示已完成數量、總數及完成比例。

AC5：父子狀態不自動連動

  • Given：父 task 包含未完成或已完成的 subtasks。
  • When：完成父 task 或全部 subtasks。
  • Then：系統不自動改變另一方狀態，父 task 狀態由使用者明確設定。

未決事項

  • 是否允許 subtask 再建立下一層。
  • 是否允許 task 與 subtask 互相轉換。
  • 是否支援批次貼上多筆 subtask。
  • 實際入口位置仍需搭配我方 task details 畫面確認。

3. 起點及操作路徑

  1. 開啟父 task。
  2. 在 task details pane 選擇 Subtasks；也可右鍵選擇 Add subtask 或使用 Tab+S。[A1]

4. 畫面呈現與可觀察行為

Subtask 嵌在父 task 中，但功能上是獨立 task，具有相同欄位；task 模型包含完成狀態、負責人與截止日。[A1][A2]

Subtask 詳細頁顯示父 task 名稱；最多支援 5 層。完成父 task 不會自動完成 subtasks。[A1]

團隊可設定「全部 sub-issues 完成時關閉 parent」或「parent 完成時關閉剩餘 sub-issues」。[L1]
